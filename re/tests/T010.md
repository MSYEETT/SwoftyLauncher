# T010 Does the save splice write an absent addon's save container back into the profile save unchanged, so its careers load again once the addon is back?

- Requested by: splicesaves, 2026-10-27
- Status: draft (scratch saves only; not for 1.5.13)
- Session: (filled by the lead when batched)

## Question
With the save splice in core, does a session without Progressive Career keep the `driver_career_progressive` container through a profile save, so the next session with the addon lists and loads the same Progressive careers, while every stock container and career stays intact?

## Hypothesis
`subsystems/game.md#save-containers` and `#save-splice`. At the profile load the root's unclaimed child bag reaches `site_Game_SaveData_UnclaimedChild`; the core writes it with `Game_SaveData_WriteBag` into its own memory (counting stream, then memory stream). At the profile save `site_Game_SaveData_ContainersCount` raises the root's containers count by the number of kept containers and `site_Game_SaveData_ContainersChildren` writes each as name, bag type id and the captured bytes. The reader reads them back as the same bags, so the Progressive mode container (and its slot manager with every career blob) is unchanged when the addon returns. Unlike T009's retain flag, nothing goes into the SAVE_DATA heap.

## Promotes
- `site_Game_SaveData_UnclaimedChild`, `site_Game_SaveData_ContainersCount`, `site_Game_SaveData_ContainersChildren`, `site_Game_SaveData_ContainersDone`, `Game_SaveData_WriteBag`, `Ne_StringTable_Lookup`, `k_Ne_BagCodecVtbl`, `k_Ne_CountingStreamVtbl`, `k_Ne_MemWriteStreamVtbl`, `g_Ne_StringTable`, `k_Ne_PropertyType_Bag`, `NeBagCodec.*`, `NeCountingStream.*`, `NeMemWriteStream.*`, `NePropertyVtbl.*`, `NePropertyTypeVtbl.*`, `NeStreamVtbl.*`: L2 -> L3.
- Any profile load error, a crash, a stock career that no longer loads, or a Progressive career missing in step 9 demotes the splice format claims (`game.md#save-splice`) and the splice stays off.

## User steps
Never use swofty's live saves. The live files are backed up first and restored byte-identical at the end. Own the game lock for the whole test.
1. Quit F1 25. In Steam, F1 25 > Properties > General: turn off "Keep game saves in the Steam Cloud".
2. Back up the live saves: `cp -a ~/.local/share/Steam/userdata/843502855/3059520/remote /mnt/work/f1-save-backups/$(date +%Y%m%d-%H%M%S)-T010-live` and write `sha256sum` of every `savegame@*` file into `MANIFEST.sha256` there.
3. Scratch save: copy `savegame@profile#NXDSMWW.BWW` and `savegame@profile#QKRHMYXE` from `/mnt/work/f1-save-backups/20261026-224729-mp-smoke/` (929,672 bytes, holds the Progressive slots) over the live ones. Record size and sha256 (S0). Keep a second untouched copy of S0 for step 10.
4. Run 1, profile A (with the addon): to the home screen. Career > Driver Career, Addons row, Progressive tile: write down every slot (name, team, season). Back out, change one harmless option in Settings > Game Options and change it back (forces a profile save), quit from the main menu. Record size and sha256 (S1); keep `loader.log` (run1).
5. Run 2, profile B (without the addon): to the home screen. Career > Driver Career > 2026 tile: continue one stock career to Team HQ, back out to the main menu without saving.
6. Still in run 2: force a profile save the same way as in step 4, then quit from the main menu. Record size, sha256 and mtime (S2); keep `loader.log` (run2).
7. Check: S2's mtime is after run 2 started, and S2's size is within about 24 KB of S1 (the 1.5.13 save backup should not report a shrink; if it does, keep its notice text).
8. Run 3, profile A again: Career > Driver Career, Addons row, Progressive tile.
9. Check: the same slots as in step 4. Continue the first one to Team HQ, play to the next weekend's first session, save, quit. Keep `loader.log` (run3). Then run profile B once more and continue the stock career from step 5 to Team HQ.
10. Control on a fresh copy of S0: run 2 again with `SWOFTY_SAVE_SPLICE=0`, then step 8. Expected: the save shrinks by about 58 KB and the Progressive tile lists no careers.
11. Restore: delete the scratch `savegame@profile*` files, copy the live ones back from step 2, check them against `MANIFEST.sha256`, turn Steam Cloud back on and check Steam reports no conflict.

## Expected log lines
- every run: `\[saves\] save splice armed` → the four hooks installed
- run 2: `\[saves\] profile load \d+: kept driver_career_progressive \((\d+) bytes\), which no loaded game mode claims` and `\[saves\] profile load \d+: kept \d+ save container\(s\) no loaded game mode claims` → the load captured the container
- run 2: `\[saves\] profile save: wrote back \d+ save container\(s\) no loaded game mode claims: .*driver_career_progressive` → the save spliced it in
- run 1 and 3: no `kept driver_career_progressive` line (the addon claims it); other kept containers (for example `driver_career_1990`) may appear in every run
- none: `could not keep`, `writing back the kept save containers failed`, `save splice did not install`, any `Ne heap error`
- game log (SaveGame channel), run 3: `Calling deserialiseSaveDataContainer\(\) on container driver_career_progressive, result .* \(OK\)`
Pass rule: the run 2 capture and write-back lines, step 7 holds, step 9 lists and loads the same Progressive careers and the stock career, and no profile load or save reports an error. Fail rule: any line from the "none" list, a profile load or save error, a crash, S2 about 58 KB smaller than S1, or a missing or unloadable career.
