## Question
Per-box DRS: does pointing swofty_f1's GameSetupMode+0x1e0 at a core-added drs.drs_allowed_lap group change the race's DRS allowed lap (g_Game_DrsLapState+0x10) for that box only?

## Hypothesis
`Sess_Parse_GameSetupMode` (L2) stores the mode's `drs_allowed_lap_group` holder at `GameSetupMode.drs_allowed_lap_group` (+0x1e0, L2). `Game_DRS_OnSessionLoad` and `Game_DRS_ResetAllowedLap` (L1) read `EntrantsManager.game_setup_mode` (+0x2b0, L1) +0x1e0 +0x10 and look the label up in the group map `Game_DRS_LoadAllowedLapGroups` (L1) built, writing RaceStart into drs+0x70 = `g_Game_DrsLapState` +0x10. If +0x2b0 is the container's element (the object the era picker swaps), a box whose rule is 200/200/200 never allows DRS in a race, and the stock f1_2024 rule (1/1/1) applies everywhere else.

## Promotes
- `GameSetupMode.drs_allowed_lap_group`, `Sess_Parse_GameSetupMode`: L2 to L3
- `EntrantsManager.game_setup_mode`, `Game_DRS_OnSessionLoad`, `Game_DRS_ResetAllowedLap`, `Game_DRS_LoadAllowedLapGroups`, `g_Game_DrsLapState`: L1 to L2 by the verify, L3 by this run
- Fail (DRS opens in the rule-200 box): demote `EntrantsManager.game_setup_mode` (the current mode is a copy, or another field)

5. Optional: a red flag or full safety car in box A: DRS stays off after the restart.

## Expected log lines
- `\[apply\] rules\.drs boot:   rules\.drs test\.drs/never: group swofty_drs_never_[0-9a-f]{8} from f1_2024` → the group row was added
- `\[drs\] box \S+ \(.*\): swofty_f1 DRS group swofty_drs_never_[0-9a-f]{8}` → the press swapped the group
- `\[drs\] box \S+ \(.*\): no DRS rule; swofty_f1 keeps its own DRS group \(f1_2024\)` → box B put it back
Pass rule: box A's race never shows `m_drsAllowed` 1 for any car; box B's race shows it from the stock lap like an unmodded race. Fail rule: box A allows DRS (the swap did not reach the session's mode), or box B never allows it (the put back failed or the label lookup missed: a missed label reads 0, DRS from the start, so DRS on lap 1 in box A also fails).
