## Question
How large are the SAVE_PROPERTY_BAG_TEMP pool and its peak use at a profile load and a profile save, without a swofty_registry entry and with 64 KB and 256 KB entries?

## Hypothesis
`subsystems/game.md#save-heaps`. A profile load decodes the whole profile into a pool made from the largest free block of SAVE_TEMP_ALLOC_HUGE (200M) or SAVE_TEMP_ALLOC (75M), and a profile save into one from SAVE_TEMP_ALLOC; `Game_CompressedSave_FreeTempPool_Thunk` logs its size and peak when it frees it. Expected: pool size in the tens of MB, load peak a few MB on swofty's profile, and each entry adds about 1.4x its payload to the load peak (base64 plus string headers) and nothing to SAVE_DATA. Nothing logs an `Ne heap error`.

## Promotes
- `Game_CompressedSave_OnReadResult` (pool notes), `Game_CompressedSave_FreeTempPool_Thunk`, `Game_CompressedSave_GetTempHeaps`, `g_Game_SaveTempAllocHeap`, `g_Game_SaveTempAllocHugeHeap`, `Ne_BagCodec_ReadBag`, `Ne_Bag_ReadValue`, `Ne_Bag_Clear`: L2 -> L3 (L1 -> L2 for `Ne_Init_TempPool_Thunk`).
- A load peak that does not grow with the entry, or an `Ne heap error` naming SAVE_DATA at a load with the entry, demotes the pool claim.

## Expected log lines
- `PropertyBagTempPool size=(\d+) sizeUsed=(\d+) peak=(\d+)` at each load and each save → the pool size and peak (record all three per run)
- `\[saves\] profile load \d+: kept swofty_registry \((\d+) bytes\)` in runs B and C → the entry's bag size
- none: `Ne heap error`, `could not keep`
Pass rule: every load and save logs a pool line, the load peak in B and C exceeds A's by at most about 2x the kept entry bytes, and no heap error. Fail rule: a heap error, a crash at load, or no pool line.
